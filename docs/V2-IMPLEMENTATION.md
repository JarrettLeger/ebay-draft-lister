# V2 foundation delivery

Built on `feature/openai-v2-ui` from master commit `6a16a15689efa10cfd11f8a970c2db13b7103768`. The original script and master are preserved.

Implemented: local FastAPI server; SQLite inventory; React/TypeScript UI; file import; manual front/back pairing, separation and swapping; OpenAI Responses and Claude Messages structured vision; editable fields and optimized titles; warnings and review checklist; explicit manual price; full-resolution Cloudinary JPEG conversion including HEIC; bounded retries/timeouts; successful-side upload caching; processing conflict protection; restart recovery; guarded eBay CSV export; secrets/configuration; Windows setup and launcher; setup/recovery documentation.

Validation: 59 pytest tests cover persistence, pairing, import failure cleanup, origin/host checks, CSV gates and legacy format, price validation, partial upload recovery, extraction contract and manual pricing, restart recovery, title optimization, HEIC/JPEG behavior, processing conflicts, Cloudinary retry payloads, batch continuation after failure, cancellation/reservations, atomic batch validation, deduplication and shutdown/restart recovery. Folder/settings tests add >100-photo sync, repeat sync, changed-file import, natural/name pairing, late back photos, user separation, corrupt files, picker recognition, Windows credential encryption, no credential echo and immediate connection use. TypeScript checking and Vite production build pass. Headless Edge exercised the actual local UI: import, edit, save, refresh persistence, export blocking and 600px layout. Additional browser checks exercised batch selection, live progress, cancellation, preservation of unsaved edits during polling, and persisted progress after reload using a simulated upload provider. A separate browser inventory verified Settings, immediate configured status, hidden credentials, a 105-photo sync producing 52 suggested pairs and one single, repeat-sync deduplication, folder persistence and narrow layout. Screenshots are in `v2-ui.png`, `v2-batch-ui.png`, and `v2-settings-ui.png`.

External APIs were mocked in tests. No API credits were spent, no photos were uploaded remotely, and no eBay drafts were created during validation. The Windows command scripts were inspected; this environment uses bundled runtimes, so clean-machine double-click setup remains to be tested. The updated locked dependencies include the Claude SDK and its HTTP client.

The next increment adds persistent background identification/upload batches, one sequential worker, live progress/cancellation, reservation conflict protection, safe restart recovery and selection of incomplete cards for processing. Existing inventory is preserved by the automatic addition of a jobs table. See the setup guide for cancellation and retry behavior.

The folder-sync increment adds a default `Z:\Match Day Cards\eBay` source, manual whole-folder rescanning, persistent source/version deduplication, filename/consecutive pairing suggestions, no 100-card processing cap, chunked picker imports, and a Settings screen with Windows-encrypted credentials. Actual source-drive reachability was checked; no real source photos were imported during testing.

Remaining: signed standalone Windows installer, continuous folder watching, AI-verified pairing suggestions, legacy sidecar/inventory import, richer QC/audit/search, versioned schema migrations, configurable shop templates and real-account acceptance checks. The legacy HTML QC/rename/repair commands are retained only in the original script; the UI replaces QC with its inventory checklist. Token usage is persisted, but dollar cost estimation is deferred. Repeated export can create duplicate drafts if the same file/cards are uploaded to eBay twice.

The provider-choice increment adds OpenAI/Claude selection, independently encrypted keys and model preferences, backward compatibility with existing OpenAI settings, provider-aware connection checks/UI labels, and provider/model provenance on cards and extraction batches. Running batches pin their selected provider/model/credentials; failures never trigger a cross-provider fallback. New tests cover the actual Claude SDK against a simulated HTTP response, both refusal/incomplete responses, missing keys, secret isolation, legacy settings, batch snapshots and provider switching. Browser verification exercised Claude then OpenAI identification using simulated responses, saved-key secrecy, provider persistence after reload, manual-price preservation and narrow layout. No API credit was used. The provider settings preview is `v2-provider-settings-ui.png`.

The export/archive increment saves a durable recovery CSV before moving originals, renames synced front/back photos into their historical source folder’s Done directory, preserves formats/bytes and local inventory copies, and journals moves for safe retry/restart. Changed/missing originals, source-drive failures and unknown source locations produce per-card archive warnings while preserving the CSV. Filename collisions never overwrite existing files. Repeated exports do not rearchive completed photos; saved CSV downloads avoid re-exporting. Eight additional tests cover selected-only archiving, durable CSV ordering/recovery, collisions, changed originals, CSV-write failures, move failures, interrupted-rename recovery and blocked exports. Browser checks verified a downloaded CSV, two renamed test originals in Done, the archive summary and an identical recovery download. No real source photos were moved during validation.

The review-workflow increment adds inventory search, task-based filters, name/photo-order sorting, filtered Previous/Next navigation, Save & next, unsaved-edit protection, a live checklist and full-resolution local photo enlargement. Select visible excludes already exported cards. A dedicated archive retry avoids generating another CSV and is gated by a saved export. Service errors now provide safe, actionable categories without echoing raw API messages. Ten additional tests cover status/network error sanitization and archive-only retry eligibility/idempotence. Browser checks verified search, filtering/sorting, exported-card exclusion, live review readiness, a full-resolution 1800px photo, Save & next persistence, archive retry without CSV creation, empty search results and narrow layouts. A preview is `v2-review-ui.png`. All external services and source photos used during verification were simulated/generated.

The desktop-window increment makes the default launcher a native Windows pywebview/WebView2 window, with a custom icon, desktop shortcut, quiet pythonw bootstrap, optional browser fallback and rotating startup logs. It reserves its own local socket, detects occupied ports before touching inventory, enables native Save As downloads, and stops its server on window exit. Close requests consult the React unsaved/running-work guard on a separate thread so WinForms never deadlocks waiting for JavaScript. Existing inventory/settings paths are preserved. Five launcher tests cover socket ownership, port collisions, failed-start cleanup and GUI lifecycle/close cancellation, bringing the suite to 59 tests. Real Windows checks confirmed rendering through Edge WebView2, hidden pythonw startup, close/server cleanup, a native CSV Save As dialog and byte-for-byte equality with the saved export. Test inventory/photos were isolated; the desktop shortcut was created for this workspace. `pytest.ini` restricts automated discovery to `tests` so scratch/native GUI helpers in ignored data folders are never collected.
