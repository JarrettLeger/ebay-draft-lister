# V2 foundation delivery

Built on `feature/openai-v2-ui` from master commit `6a16a15689efa10cfd11f8a970c2db13b7103768`. The original script and master are preserved.

Implemented: local FastAPI server; SQLite inventory; React/TypeScript UI; file import; manual front/back pairing, separation and swapping; OpenAI Responses and Claude Messages structured vision; editable fields and optimized titles; warnings and review checklist; explicit manual price; full-resolution Cloudinary JPEG conversion including HEIC; bounded retries/timeouts; successful-side upload caching; processing conflict protection; restart recovery; guarded eBay CSV export; secrets/configuration; Windows setup and launcher; setup/recovery documentation.

Validation: 36 pytest tests cover persistence, pairing, import failure cleanup, origin/host checks, CSV gates and legacy format, price validation, partial upload recovery, extraction contract and manual pricing, restart recovery, title optimization, HEIC/JPEG behavior, processing conflicts, Cloudinary retry payloads, batch continuation after failure, cancellation/reservations, atomic batch validation, deduplication and shutdown/restart recovery. Folder/settings tests add >100-photo sync, repeat sync, changed-file import, natural/name pairing, late back photos, user separation, corrupt files, picker recognition, Windows credential encryption, no credential echo and immediate connection use. TypeScript checking and Vite production build pass. Headless Edge exercised the actual local UI: import, edit, save, refresh persistence, export blocking and 600px layout. Additional browser checks exercised batch selection, live progress, cancellation, preservation of unsaved edits during polling, and persisted progress after reload using a simulated upload provider. A separate browser inventory verified Settings, immediate configured status, hidden credentials, a 105-photo sync producing 52 suggested pairs and one single, repeat-sync deduplication, folder persistence and narrow layout. Screenshots are in `v2-ui.png`, `v2-batch-ui.png`, and `v2-settings-ui.png`.

External APIs were mocked in tests. No API credits were spent, no photos were uploaded remotely, and no eBay drafts were created during validation. The Windows command scripts were inspected; this environment uses bundled runtimes, so clean-machine double-click setup remains to be tested. The updated locked dependencies include the Claude SDK and its HTTP client.

The next increment adds persistent background identification/upload batches, one sequential worker, live progress/cancellation, reservation conflict protection, safe restart recovery and selection of incomplete cards for processing. Existing inventory is preserved by the automatic addition of a jobs table. See the setup guide for cancellation and retry behavior.

The folder-sync increment adds a default `Z:\Match Day Cards\eBay` source, manual whole-folder rescanning, persistent source/version deduplication, filename/consecutive pairing suggestions, no 100-card processing cap, chunked picker imports, and a Settings screen with Windows-encrypted credentials. Actual source-drive reachability was checked; no real source photos were imported during testing.

Remaining: native Windows installer/window, continuous folder watching, AI-verified pairing suggestions, legacy sidecar/inventory import, richer QC/audit/search, versioned schema migrations, configurable shop templates and real-account acceptance checks. The legacy HTML QC/rename/repair commands are retained only in the original script; the UI replaces QC with its inventory checklist. Token usage is persisted, but dollar cost estimation is deferred. Repeated export can create duplicate drafts if the same file/cards are uploaded to eBay twice.

The provider-choice increment adds OpenAI/Claude selection, independently encrypted keys and model preferences, backward compatibility with existing OpenAI settings, provider-aware connection checks/UI labels, and provider/model provenance on cards and extraction batches. Running batches pin their selected provider/model/credentials; failures never trigger a cross-provider fallback. New tests cover the actual Claude SDK against a simulated HTTP response, both refusal/incomplete responses, missing keys, secret isolation, legacy settings, batch snapshots and provider switching. Browser verification exercised Claude then OpenAI identification using simulated responses, saved-key secrecy, provider persistence after reload, manual-price preservation and narrow layout. No API credit was used. The provider settings preview is `v2-provider-settings-ui.png`.
